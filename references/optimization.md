# 自我优化机制

## 为什么必须有这一层

技能是文档，它不会自己变好。**但它每一次被使用，都会暴露问题。**

问题暴露了却不写回去，下一个用户会踩同一个坑。这就是大部分"做了一次就废掉"的技能的死因——它们只被设计过一次，从没被使用反馈修改过。

**判断一个技能是否成熟：看它有没有被真实使用改过。**

---

## 四步复盘（每次实战结束后做）

### 第 1 步 · 定位卡点

回看整段对话，找**用户第一次说"不会 / 不懂 / 懵 / 啊？"的那一句**，以及它前面我讲的那一段。

这一段就是问题所在。不要往后看——后面的内容都是在错误基础上叠加的。

记录格式：
```
卡点位置：讲「XXX」那一段
用户原话：「不会」
前面我讲的是：「<原话摘录>」
```

### 第 2 步 · 归因

二选一，不要含糊：

| 归因 | 判定 | 含义 |
| --- | --- | --- |
| **知识缺口** | 换 2–3 种说法仍不懂 | 他不知道某个前置概念 |
| **讲法问题** | 换一种说法就懂了 | 概念知道，表述跨了步 |

判据只有一个：**换说法试一次。** 能懂就是讲法问题。

### 第 3 步 · 反哺

按归因走不同路径：

| 归因 | 改哪个文件 | 怎么改 |
| --- | --- | --- |
| 讲法问题 | `references/teaching.md` | 把新的说法加进示例；把踩雷的表述列进"讲法问题自查清单" |
| 知识缺口 | `references/foundations.md` | 在"常见缺口清单"加一行；或在诊断阶梯里加一层 |
| 顺序问题 | `SKILL.md` Stage 0.5 | 调整退层阶梯，或把某个探测题提前 |
| 节奏问题 | `references/modes.md` | 调时间块长度、调模式阈值 |
| 取题问题 | `references/sourcing.md` | 补来源、补搜索式、补假材料特征 |

### 第 4 步 · 升版本

| 改动性质 | 版本位 | 例子 |
| --- | --- | --- |
| 改措辞、补示例 | patch（1.1.0 → 1.1.1） | 把某句话换个说法 |
| 加结构（新阶段 / 新 reference） | minor（1.0.0 → 1.1.0） | 新增 Stage 0.5 |
| 改主流程 | major（1.0.0 → 2.0.0） | 流水线重排 |

CHANGELOG 条目必须写明**触发原因**，不能只写"优化了讲法"：

```
## [1.1.0]
### 由实战反馈驱动
- 现象：用户答不出"差半个波长亮还是暗"
- 归因：知识缺口（波长概念未建立）+ 讲法问题（"走了 3 个波长"过于抽象）
- 修改：新增 Stage 0.5 基础诊断；新增 references/foundations.md
```

## 信号识别表

用户不会直接说"你讲得太难了"。要用这些信号反推：

| 用户说的话 | 真实含义 | 反哺到 |
| --- | --- | --- |
| "不会"（连续两次） | 起点太高，或退得不够 | 阶梯下移；foundations 加缺口 |
| "懂了"但下一题答错 | 假懂——验证题太容易或太像原题 | teaching.md：验证题必须换问法 |
| 反复追问同一个词 | 术语没解释 | 建术语表前置 |
| 突然换话题 | 节奏太快，跟不上又不好意思说 | modes.md：缩短单块时长 |
| "能不能再说一遍" | 讲法单一，只有一条路 | teaching.md：每概念备 2 种讲法 |
| 只回一个字（"嗯""哦"） | 已经被动跟不上了 | 立刻停下来验一道 |
| 自己总结出规律 | 真的懂了 | 把他的话记下来当标准表述 |

## 反向信号：什么时候不该改技能

不是所有卡顿都是技能的问题。这几种情况改技能反而有害：

| 情况 | 该做什么 |
| --- | --- |
| 用户根本没看，直接说不会 | 让他先试一次，别急着改 |
| 用户时间太紧，主动放弃某考点 | 这是正常取舍，不是技能缺陷 |
| 某个学科特有的怪题 | 记为个案，不改通用流程 |
| 用户明确要求"别讲这么细" | 这是偏好，记进模式参数，不改讲法 |

**判断标准：同样的卡点在 2 个以上不同用户/不同课程上出现，才是技能的问题。** 只出现一次，先记为观察。

## 同步到远端仓库（第 5 步，必做）

**优化只改本地 = 优化没发生。** 下一个人下载到的还是旧坑。

默认仓库：`github.com/shizhanhshuo/exam-cram`（main 分支 + 每版一个 Release）

### 标准流程

```
1. 改本地：~/.workbuddy/skills/exam-cram/
2. 升 version + 写 CHANGELOG
3. 同步到本地仓库副本：exam-cram-repo/
4. 打包：dist/exam-cram.zip（必须排除 .git，用 Python 重建，不要原地覆盖）
5. 提交：blob → tree → commit → PATCH ref
6. 打 Release + 上传 zip
7. 回读远程文件确认版本号已更新
```

### 踩过的坑（照这个避开）

| 坑 | 表现 | 正确做法 |
| --- | --- | --- |
| `git push` 不通 | 8000+ 端口拒绝 / 443 超时（代理与墙） | 全程走 GitHub REST API：`ref → base_tree → POST /git/blobs → POST /git/trees → POST /git/commits → PATCH /git/refs/heads/main` |
| 空仓库报 409 | `Git Repository is empty` | 先 `PUT /contents/README.md` 造第一个 commit，再走 tree/commit |
| 中文 JSON 乱码 | 提交后中文变问号 | 必须 `[System.Text.Encoding]::UTF8.GetBytes($json)` |
| 打包带上 `.git` | zip 体积暴涨、解压出乱码目录 | 用 Python `shutil.copytree(ignore=shutil.ignore_patterns('.git'))` 重建，不要 `Copy-Item -Recurse` 覆盖 |
| 原地覆盖残留旧文件 | dist 里出现已删除的目录 | 先 `rmtree` 再 `copytree` |
| 只提交不打包 | 仓库是新的，zip 是旧的 | 每次都必须重建 zip 并重新上传 Release asset |

### 取 token（shizhanhshuo 账号）

```powershell
$in = "protocol=https`nhost=github.com`n`n"
$t = (($in | git credential fill 2>&1) | Where-Object { $_ -match '^password=' }) -replace '^password=',''
```

**token 不进任何文件，也不写进 CHANGELOG。**

### 提交后必须做的事

回读一次远程 `SKILL.md`，确认 `version:` 行已经是新版本号。**不确认就等于没提交。**

## 实战复盘记录

按时间倒序。每次实战加一条。

### 2026-11-15 · 大学物理 C（下）· 公式梳理轮：用户连续四轮只问符号

**现象**：用户连续追问「双缝的 x 是什么」「迈克尔逊公式」「光栅缺级」「d、a 是什么」，全程不做题。不是卡在某一步，而是在自己重建符号表。

**归因**：**不是讲法问题，是缺少一张可随时回看的符号表。** 讲题时符号随讲随过，用户当时点头，但脱离上下文（换个模型、隔一天）就断线。追问的都是同一个东西：这个字母量的是图上哪一段。

**反哺**：讲完任何模型，**必须紧跟一张固定四列的符号表**：

```
| 字母 | 图上是哪一段 | 题目常见说法 | 单位 |
```

禁止只在正文里用文字描述符号位置（"x 是屏上量出来的一段距离"这种说法用户看完仍会再问一次）。

**判据**：同一模型被追问两次以上符号 → 直接补表，不再重复解释；补表比换说法有效。

### 2026-11-13 · 大学物理 C（下）期中 · 第 2、3 题

**卡点序列**（一次实战连爆五个，逐条记）：

1. 讲第 2 题（薄膜）时，一句话里同时引入 **相长干涉 / 折射率 n / 光程 2nd / 半波损失** 四个新概念 → 用户反问"相长干涉是什么，还有这个 n 是什么意思"
2. 讲半波损失时给的是**规则表格 + 口诀** → 用户直接问"半波损失是什么"（讲了两遍都没落地）
3. 问"下表面 1.5 → 1.7 翻不翻" → 用户答"不要？"（判断错，把两种固体都当成"密"）
4. 问"3d = 600，d = ？" → 用户答"不知道"（卡在符号不是卡在算术）
5. 讲完第三题原理 → 用户连问"什么叫迈克尔逊干涉仪""这个仪器长什么样子"

**归因**：

| # | 归因 | 依据 |
| --- | --- | --- |
| 1 | 讲法问题 | 违反自己写的"一次只讲一个概念" |
| 2 | 讲法问题 | 换讲法（波形翻转图）后立刻通了 → 说明概念能接住，是表述跨步 |
| 3 | 讲法问题 | 用形容词"疏/密"代替可视化比较 |
| 4 | 讲法问题 | 把 `2nd` 当整体处理，没逐字拆 |
| 5 | **知识缺口（新层）** | 换说法也不通，因为他根本不知道有这台仪器 → 需要新增实物层 |

**有效 / 无效对照**：

| 无效做法 | 有效做法 |
| --- | --- |
| 规则表 + 口诀（半波损失） | "反射回来的波翻了个身" + 翻转波形图 |
| 文字说"疏 → 密，往右" | 数轴 1.0 — 1.5 — 1.7，看箭头方向 |
| 直接给 `2nd = kλ` | 逐字翻译表 + 化简成 `3d = 600` |
| 只讲光路不讲装置 | 俯视外观图 + "它是一台测极小长度的仪器" |
| 一个界面一个界面问 | 先给三行 n，再一次性比对 |

**修改**（→ v1.2.0）：

1. `foundations.md` 新增 **L-1 实物层**（比"现象"更底的一层）
2. `foundations.md` 新增三个手法：**A 符号逐字翻译法、B 数轴法、C 迁移复用**
3. `foundations.md` 物理缺口表补 5 行（n、相长/相消、半波损失、仪器、复合符号）
4. `SKILL.md` 纪律新增第 7 条：**一次只引入一个新概念**

**核心结论（本条最值得复用）**：

> 零基础用户的卡点不在公式层，而在下面四层，顺序是：
> **名词层（这词指什么）→ 实物层（长什么样）→ 比较层（谁大谁小）→ 符号层（每个字母什么意思）**
> 公式层反而是最后一层，也是最不容易卡的一层。
>
> 所以讲一道题之前，先扫这四层，扫完再进推演。跳过任何一层，后面必崩。

**遗留问题**：
- 补课已经吃掉大量时间，五道题只推进到第三题。下一轮要评估是否该停止逐个补概念，改为"边做边补"
- 用户从不主动说"这里不懂"，都是等讲完再追问名词。**应该每讲完一个小节就主动点一个名词问"这个词现在清楚吗"**

### 2026-11-04 · 大学物理 C（下）期中 · 用户基础极差
